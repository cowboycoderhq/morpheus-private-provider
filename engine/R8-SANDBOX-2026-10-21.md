`/Applications/Xcode.app` (`DEVELOPER_DIR` set by `scripts/bundle.sh`).
Branch `feat/sealed-v2-splash-engine`. Signed test copy: `build/r8/SealedEngineV2.app`,

App Attest CD hash `<h1>`.

## What R8 does and does not do

The engine applies a Seatbelt (SBPL) profile to itself with
`sandbox_init_with_parameters`, then runs a self-test before it serves a prompt.
The sandbox limits what the engine process can do after that point:

- no file writes anywhere, and no file reads outside the system volume
  (`/System/Library` per directory, `/usr/lib`, `/usr/share`);
- no exec and no fork (no helper processes);
- no outbound sockets of any kind (TCP, UDP, AF_UNIX), no new listener, no
  bind on any address;
- no mach lookup except `com.apple.devicecheckd`;
- no process information or signals for any process except its own children.

R8 does **not** encrypt or hide the engine's memory. Root can still read the
prompt plaintext in engine memory while it is decrypted there (task port as
root, dtrace, a core file through the kernel). R8 shrinks the attack surface of
the engine process itself: a compromised engine (for example, a bug in the
HTTP parser or the tokenizer) cannot write the plaintext to a file, start a
debug helper, or send it out over a socket.

## Start order (engine)

1. R1 guard, environment allowlist, LaunchServices registration (unchanged).
2. Read the package once and hash it; start and verify the child; make and
   attest the App Attest key (unchanged).
3. **New:** bind and listen on `127.0.0.1:<port>` and wait until the listener
   is ready. Until step 5, every request gets 503 `not ready`.
4. **New:** `sealed_r8_enter`: run the 30 arms without a sandbox (controls),
   apply the profile, check `sandbox_check(getpid())` = 1, run the 30 arms again
   (each must be denied), then two "must still work" arms on the child.
   Any failure: `sandbox refused: <arm>` in the log, exit 7.
5. **New:** mark the engine sandboxed; log `listening … sandbox=R8`; serve.

The listener moved before the sandbox because of a measured SBPL limit (below):
any bind or inbound rule with a port also allows that port on every interface.

## The profile (as applied, from `build/r8/engine.log`)

The `/System/Library` list is built at run time from the directory listing
(the R5 method); its 170 entries are shortened here.

```
(version 1)(deny default)
(allow file-read*(subpath "/System/Library/Image Capture")(subpath "/System/Library/Receipts") … (subpath "/System/Library/InternetAccounts"))
(allow file-read*(subpath "/usr/lib")(subpath "/usr/share"))
(deny process-info*)
(allow process-info* (target children))
(allow signal (target children))
(allow mach-lookup (global-name "com.apple.devicecheckd"))
(deny file-read*(subpath "/System/Volumes/Data"))(deny file-read*(subpath "/usr/share/snmp"))(deny file-read*(subpath "/System/Library/CoreServices/CoreTypes.bundle/Contents/Library"))
```

The excluded `/System/Library` folders (firmlinks to the Data volume): `Caches`,
`Assets`, `AssetsV2`, `PreinstalledAssets`, `PreinstalledAssetsV2`, `Speech`.

## Every allowance, with its justification

| Rule | Why | Evidence |
|---|---|---|
| `file-read*` on `/System/Library/*` (170 dirs, not the 6 firmlinked ones) | Frameworks and their resources load lazily after the sandbox (Foundation, Network, DeviceCheck, CryptoKit). Kept from R5 unchanged. | R5 measurement; the record run here showed no system read outside the rules (below). |
| `file-read*` on `/usr/lib`, `/usr/share` | Swift runtime and dylibs; ICU data `/usr/share/icu/icudt78l.dat` is opened on the first request (tokenizer/template text). | Record run: `file-read-data /usr/share/icu/icudt78l.dat`. |
| `(deny process-info*)` (a deny, listed because it is required) | **Measured: `(deny default)` does not cover `process-info*` on 27.2.** Without it, `proc_pidinfo`, `proc_pidpath` and `KERN_PROCARGS2` (the full argv and environment) of any process of the user succeed in the sandbox. | `/tmp/r8-pid.c` test; arms `pidinfo-other-process`, `procargs-other-process`. |
| `(allow process-info* (target children))` | The per-request child identity re-check (`csops_audittoken` CD hash and status word), the reap (`waitid`, `proc_pidinfo` unique id) and the S-5 gate in `sealed_spawn.c`. | Mutant `SEALED_R8_TEST_NO_CHILD_RULES`: arm `child-pidinfo` is refused and the engine refuses to serve. |
| `(allow signal (target children))` | `sealed_child_kill` (SIGKILL) at shutdown and on a fault. Signals to any other process stay denied. | Arm `child-signal0` (allowed) and arm `signal-other-process` (denied). |
| `(allow mach-lookup (global-name "com.apple.devicecheckd"))` | `DCAppAttestService.generateAssertion` for `POST /session` and `POST /probe` goes to devicecheckd. Without the rule: deny report `mach-lookup com.apple.devicecheckd`, and `/session` returns 503 `assertion refused`. | Run of <date> <time> (deny log), then the passing run with the rule. |

What is **not** allowed, and why that works:

- **No network rule at all.** The listener is bound and listening before the
  sandbox. `accept`, `read` and `write` on it need no rule (measured with
  `/tmp/r8-accept.c`: with `(deny network*)` and no allow, a pre-bound listener
  accepted a curl and answered 200; a second bind was refused with EPERM).
- **No egress for App Attest.** Key generation and attestation happen before
  the sandbox (step 2). After it, assertions need only the devicecheckd lookup;
  the engine itself makes no connection to Apple. (The daemon does its own
  networking outside the engine's sandbox.)
- `com.apple.diagnosticd` lookups and the read of
  `/Library/Preferences/Logging/com.apple.diagnosticd.filter.plist` are
  denied. They come from `os_log` in system frameworks. Nothing fails without
  them; denying them also keeps the engine from sending to the diagnostics
  daemon.
- `process-info-pidinfo self` is denied (8 reports per run, from a framework
  that reads its own process info). Nothing fails without it.

### The SBPL bind limit (measured, the reason for the start order)

On 27.2 beta 27.2-beta, with `(deny network*)` plus one of
`(allow network-bind (local tcp "localhost:N"))`,
`(allow network-bind (local ip "localhost:N"))`,
`(allow network-bind (local tcp4 "localhost:N"))` or
`(allow network-inbound (local tcp "localhost:N"))`, a process can bind
`127.0.0.1:N`, `0.0.0.0:N` **and** the Mac's LAN address `<lan-ip>:N`.
Only the port is checked. The first R8 self-test caught this (arm
`bind-port-all-interfaces` was not denied with the bind rule, and
`bind-port-lan-address` was not denied with only the inbound rule). The fix is
to have no network rule and to bind before the sandbox.

### Record run (method)

`scripts/r8-record.sh` with the test switch `SEALED_R8_TEST_RECORD`: at the R8
point the profile is `(allow default (with report))`, so every operation is
logged by the kernel as `Sandbox: SealedEngine(pid) allow …`, readable by
the user with `log stream`. One `/attest` and one verified chat ("Paris") gave
7 distinct operations: `system-info net.link.addr` (4), `sysctl-read
net.routetable.0.0.3.0` (2), `network-bind` and `network-inbound` on the port
(from the old start order), `mach-lookup com.apple.devicecheckd`, and the ICU
data file. Under enforcement, `net.link.addr` and `net.routetable` are not
reported as denials and nothing fails; they come from the listener setup,
which now happens before the sandbox.

## Known limits (not closed)

- **No memory protection.** Root can read the engine's memory (prompt
  plaintext, session keys) while the engine runs. R8 does not change that.
- **The sandbox starts after start-up.** The package read, the child spawn and
  the App Attest key generation happen before the sandbox, with the full
  rights of the user. No consumer plaintext exists in that phase, and every
  request in it gets 503, but a compromise of the start-up code is not
  contained.
- **The listener's address is set by code, not by the profile.** No SBPL rule
  can restrict a bind to loopback on this macOS (measured). The engine binds
  `127.0.0.1` before the sandbox; arms 18 and 19 prove no second bind is
  possible after it. The check script confirms the one listener with `lsof`.
- **devicecheckd is reachable.** A compromised engine can still ask devicecheckd
  for assertions with its own key (that is the engine's job). It cannot reach
  any other named service.
- **`/System/Library` is broad.** Reads of the sealed system volume are
  allowed (the R5 rule). That volume holds no user data; the Data-volume
  firmlinks inside it are denied.
- **Not tested here:** the published `build/SealedEngineV2.app` was not
  rebuilt or replaced, and `scripts/start-engine.sh` / `scripts/evidence.sh`
  were not rerun with R8 (`start-engine.sh` kills every engine whose path
  matches, which would have hit the engine that ran on 29452). The R8 copies
  have their own CD hash; the published CD hash in the README is the pre-R8
  build. The reproducibility check (`sealed-verify rebuild`) was not rerun for
  the R8 source.
- The root kit arms for the engine (`tee-rootpass.sh`, "P10 engine") did not run.
- Development signing, borrowed App ID, one Mac (unchanged from the README).
- The engine that ran on port 29452 (pid 41210) was found with a defunct child
  (41282, `<defunct>`). It later exited on its own child identity re-check
  (`serving: csops cdhash failed errno=3`, `backend fault; stopping`,
  `build/engine.log` last written <time>). This work did not signal it; the
  R8 scripts use ports 29453–29455 and only stop copies under their own folder.
