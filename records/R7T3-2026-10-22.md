# R7-T3 late-phase check — 2026-10-22

Host Mac17,7, macOS 27.2-beta. Run: `neg/r7t3-2026-10-22.txt` (build <time>). Verdict: **PASS**.

## Question

After Metal device creation and model load, do framework actions (a signal handler, a task or thread port, a consumed sandbox extension, credentials change) or a busy-poll thread leave a state that the child's start-time self-test would have refused? Prior evidence covered only the "sandboxed" phase and a static import check, both before Metal and load.

## Method

- **A / C:** 20-request workloads with a busy-poll thread (`A` and `C` differ by environment; `M` is a 4-request short run). Read-backs after each phase: sandboxed, own signals, after load, loaded, around requests, at the end. The R5 self-test runs again at the end.
- **B:** four seeded controls injected at request time: a SIGSEGV handler, a task port and a thread port, a consumed sandbox extension, and a setgid. Each must make the read-back report CHANGED.
- **Q:** the same four seeds at load, plus a static initializer that sets a task port before the guard.
- **E:** the crash test moved to "loaded" and to after a request, with and without the guard.
- **Interposer:** counts seeded calls and their reach; records signal and port calls after the guard.

## Verdict and reading

PASS against the written criteria: the read-backs match after load, around each request, in the busy-poll, and at the end. All seeded controls fired. The end self-test held.

Two results need precise reading:

1. **After-request crash with the guard:** `crashed=1`, `exception_seen=0`, 0 reports. The guard absorbed the fault on its own thread, so the oracle saw no exception and no crash report existed. The control (no guard) shows the same fault reaching the oracle with a report. That is the guard working, not a failure.
2. **Long generation:** the design wanted a 5-minute single generation. None occurred; the longest was 270.3 s. Recorded INFO rather than a false PASS.

## Residual risk

- The interposer proves reach at the Metal caller and counts only the child's own calls. It does not enumerate every framework action.
- The read-backs sample four classes. A change in another class would not be seen.
- These results hold for this Mac and macOS build. Re-run on each new macOS.
