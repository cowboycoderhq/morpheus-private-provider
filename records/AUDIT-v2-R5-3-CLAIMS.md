Scope: the four public files of the staged release tree (`README.md`, `docs/REBUILD.md`, `model/README.md`, `records/README.md`) and the staged `records/` copies.
Candidate pins: child `8083a338…`, engine `<h17>…`, model `57b2151c…`, engine commit `<h98>`, child commit `aa32be84`, harness commit `<h99>`.
Method: read-only. I used `cat -n`, `grep`, `diff`, `cmp`, `shasum`, `codesign -dvvv`, `git archive` / `git status` / `git merge-base`, `make -n check-build-identity` and `make check-build-identity` (a read-only compare; the child repo stayed clean), `scripts/model-hash.py`, Python parsing of `sealed-manifest.bin` and the report JSON, and `stage.py --check`. Reviewer: one model (Claude family). This is not an independent review. Line numbers are from `cat -n` of the staged files.
Identity rule: this report names no identity string. Where a file holds one, the report gives the file and the line.

## Pre-registered falsifiers

My verdict is "not ready to publish as written". These results would make the verdict false:

1. Every public statement about records, rebuilds and accept reports is scoped to the build that it describes.
2. Every limit in `CLAIM-v2-2026-10-24.md` and `SPEC-TEMP-2026-10-25.md` is in the README limits, or the README says plainly that the list is partial.
3. The redaction statement in `records/README.md` is complete and true for a sample of 10 or more files.
4. No public sentence says more than the records support. Examples: "checks", "without trusting", "byte for byte".
5. Every pin, hash, commit and revision in the public text matches a live source.

Result: falsifier 5 holds (all pins match). Falsifiers 1, 2, 3 and 4 fail (findings below).

## Verdict

All pins, hashes, commits, the HF revision, the manifest and the router digest are correct against live sources. The public text is not ready. It claims more than the records support: the router "checks … without trusting the provider", and the records and rebuild are described as being for "this build". It cites records and a second-Mac rebuild of the previous, now revoked build as if they cover the candidate pins. It leaves out several limits of the claim, including the provider-trust limit and the temperature-0.6 signal. A staged record still holds a host name that the stage gate does not catch. A redaction also made a false macOS version. Fix R5-3-01 to R5-3-05 before publication. Fix R5-3-06 to R5-3-08 before publication or in the same pre-release. The LOW and INFO items can follow.
