## Claim

On a Mac in Full Security, with the macOS kernel and sandbox not damaged:

1. **Prompt.** Root cannot read the prompt from the memory of the engine or the child.
2. **Reply.** Root cannot read the reply to the prompt from the memory of the engine or the child, or from the connection between the provider and the consumer.
3. **Model.** Root cannot change the model without a change to the model hash that the consumer checks.
4. **Surface.** The child cannot open `IOSurfaceRootUserClient`.
5. **Identity.** The engine that runs is the binary whose CD hash the consumer pins. The consumer checks that CD hash on each assertion.

## Limits that apply to the reply

1. **Reply length.** The sealed frames show the length of the reply to an observer. The engine seals the reply in chunks, so the number and size of frames depend on the reply text. Padding is not used.
2. **Error text.** The 503 reply for a KV budget refusal sends the child's error text without the seal. The text gives a number derived from the prompt length (audit E-01). This must be fixed.
3. **GPU memory.** The reply tokens pass through GPU memory in the child. No root arm tests a read of GPU memory (P6, audit C5-04).
4. **Freed KV memory.** The chunked KV cache frees memory that held prompt and reply data while the child runs. No test shows that the system clears those pages before a different task gets them (audit K-2).

## Limits that apply to the whole claim

- No memory encryption for third-party code on Apple Silicon. A kernel defect breaks the claim.
- The engine does not check SIP, swap encryption, or `hibernatemode` (audit C5-10). These are reported by the provider.
- The current engine build (`<h69>`) has no accept run.
- The source is not public, and no second party rebuilt the current build.
