## Mechanism (from the code)

Each decode step emits one tokens frame. Its token count is `retained` = 1 + the number of draft tokens the main model accepted (`model/Runtime.mm`: `laneResult.retained`, `laneResult.accepted`; at most `kDraftProposalTokens` = 7, so 1 to 8 tokens). The child sends that step's tokens as one frame (`engine/Engine.cpp` `events_.tokens(...)`, `engine/NativeRuntime.cpp` `send(TokensEvent)`). So the frame size equals the acceptance count of that step, and acceptance depends on how predictable the next tokens are.

Mean tokens per frame: 8.00 and 8.00. Criteria result: NO SIGNAL.

## Why this does not exclude the signal

- Both prompts asked the model to **repeat** or **continue** a pattern. A random word that is already in the prompt is easy for the draft model to copy, so the draft was accepted at the maximum on both. The unpredictable case was not unpredictable for the model.
- Every run stopped at the 40-token budget after 5 full steps, so no step had a lower count.
- A fair test needs a reply the draft model cannot guess: open-ended text, or a reply whose content is not in the prompt.

## Status

- The claim keeps this as a limit: frame sizes are the per-step acceptance count, which can depend on content. Measured here: no difference between a sequence and a copied random string. Not measured: open-ended text.
- A follow-up test with open-ended prompts would settle it.

## Correction (2026-10-25, audit R4-5-02, R4-5-03)

- A frame holds 1 to 9 tokens: up to 8 retained rows plus one terminal token (stop or last budgeted token). The last frame of a reply can therefore not show the acceptance count.
- Both prompts here were copy tasks, so the test could not show a difference. `sealed-chat` sends temperature 0, so each prompt gave the same reply 4 of 4 times.
- Follow-up test with open-ended prompts at temperature 0 and 0.6: `review/SPEC-TEMP-2026-10-25.md`.
