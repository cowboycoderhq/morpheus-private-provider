## The client the child actually holds

`ioreg -c IOGPUDeviceUserClient` matches live `AGXDeviceUserClient` objects. `AGXDeviceUserClient` is a subclass of `IOGPUDeviceUserClient`, so the SBPL rule `(allow iokit-open (iokit-user-client-class "IOGPUDeviceUserClient"))` admits the Apple-Silicon GPU client. The child holds one for Metal (`MTLDevice`). The class name in the profile is therefore not a leftover: it names the base class of the live GPU client.

P6 is the decisive leg for P1 and P2. Both Metal handles are XPC-coder-only. A handle therefore leaves the process only inside an XPC message, and an XPC message needs one of two directions: the child registers a Mach service (`mach-register`), or the child looks up a service (`mach-lookup`). The profile has `(deny default)` and one `mach-lookup` rule (`com.apple.MTLCompilerService`). Neither direction is allowed for an arbitrary name.

### Amendment before the run: the handle is XPC-only

The first design put the handle bytes in the reason file and had the reader decode them. The pre-run measurement above voids that leg for a different reason than the sandbox: `MTLSharedTextureHandle` and `MTLSharedEventHandle` cannot be encoded by `NSKeyedArchiver` at all. `-[IOSurface encodeWithCoder:]` throws `This object may only be encoded by an NSXPCCoder`. So the handle is not a byte object. P1 and P2 are therefore decided on three measured legs:

1. **Creation** under the profile (the child may still hold the object).
2. **Transport** (P6) — the child's two XPC directions, with the control firing.
3. **Discovery** (P1b, P4, P5) — the reader's attempts to find the object with no handoff.

The narrow leg that this design does **not** measure is the actual XPC handoff: a launchd-registered Mach service that carries the handle to the reader, with and without the sandbox. That needs a LaunchAgent, which is a system change, and a probe variant that connects with `NSXPCConnection`; neither exists in this kit. Residual risk 3 names what it would take. Until that leg runs, the report says "no transport available to the child", not "an XPC handoff was refused".

The reason file still carries the handle bytes when a future macOS lets them encode (`encode=ok`); the reader decodes them then. On this macOS the reader's tex and event arms print `NO-HANDLE`, which is a finding, not a failure.

## Residual risk

1. **The blocking rule is inferred, not isolated.** The measured fact is: under the production profile the three creation APIs return nil; without the sandbox they work. The strongest available evidence for the cause is T2C's single refused `IOSurfaceRootUserClient` open per child and the nil `newSharedEvent`. The isolating test is a build with `-DSEALED_TEST_PROFILE_ALLOW_IOSURFACE -DSEALED_TEST_S1_SHARE` **and** the self-test arm iosurface-open skipped (`sealed_r5.mm:356-368` refuses a permitted open, so that build exits 113 before the hook). If a future backend removes the deny, P1, P2 and P5 reopen together.
2. **Undocumented external methods were not probed.** `IOGPUDeviceUserClient`/`AGXDeviceUserClient` carry private selectors (`IOGPUCommandQueue`, allocations, `IOGPUClientSharedMachine`). Calling unknown selectors can panic the GPU driver, so the test used only public Metal and IOKit calls. A compromised child with the class allowed could try them; that risk is not measured here.
3. **The XPC handoff leg is not measured.** If a later backend lets the child make shared objects again, the handle still has to leave by NSXPC, and that needs a launchd Mach service plus a probe variant that connects with `NSXPCConnection`. Neither exists in this kit. Today the creation result makes the leg moot.
4. **The registry is globally readable.** Any process reads `AGXAccelerator` properties (37 here), including `AGCInfo.fLastSubmissionPID` and `PerformanceStatistics`. None carries child data. `SurfaceList` was empty in both phases. A covert channel of one pid-sized value through submission statistics was not analyzed.
5. **One Mac, one build, one request shape.** M5 Max, `27.2-beta`, no model request during the hooks. A serving child holds KV pages; the probe did not run mid-request.
6. **A different non-root user was not tested.** The reader runs as uid 501, as in T2.
7. **P4 does not test `IOServiceOpen` against another process's live user client.** That is not possible through IOKit; `IOServiceOpen` always makes a new client.
