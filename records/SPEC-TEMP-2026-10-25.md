# Temperature test of the speculative-step pattern — 2026-10-25

Audit item: R4-5-03 (follows `review/SPEC-STEP-2026-10-24.md`).
Script: `neg/LEN/temp-root.sh`, grader `neg/LEN/temp-grade.py`. Run folder: `neg/LEN/temp-20261025-<time>/` (`report.txt`, `verdict.txt`, one `fs_usage` trace per run).

## Build and setup

- Engine pid 5473, CD hash `<h18>` (equal to the kit pin); child pid 5556 (`<h17>…`). macOS 27.2-beta, SIP enabled.
- Root ran only `fs_usage -w -f filesys <child pid>`. The user sent the chats through the installed kit's `sealed-chat` (64 tokens).
- 4 open-ended prompts on different topics (the reply is not in the prompt): a lighthouse at night, bicycle gears for a child, a complaint letter about a late train, reasons for houseplants. 3 runs each at temperature 0 and at temperature 0.6.
- A tokens frame is a child write of 24 + 16 + 4 × n bytes; n is the token count of one decoding step.

## Criteria (written in the script before the run)

- REPEATS-AT-0: at temperature 0, for at least 3 of the 4 prompts, the 3 runs give the same sequence.
- DISTINCT-AT-0: at temperature 0, the 4 prompts give 4 different sequences.
- SIGNAL-AT-0.6: at temperature 0.6, for at least one pair of prompts, the means of tokens per frame differ by more than 2 × the largest per-prompt standard deviation.

## Result

| Verdict | Result |
|---|---|
| REPEATS-AT-0 | **YES**: 4 of 4 prompts gave the same sequence in all 3 runs |
| DISTINCT-AT-0 | **YES**: 4 different sequences |
| SIGNAL-AT-0.6 | **YES**: largest difference 3.17 tokens per frame (complaint letter 5.52 against lighthouse 2.35); margin 0.84 |

Temperature 0, one sequence per prompt (the same in all 3 runs):

- lighthouse: 24 frames, `[3, 1, 6, 3, 1, 3, 1, 1, 3, 6, 4, 3, 2, 1, 2, 2, 1, 4, 1, 4, 4, 4, 1, 3]`
- bicycle gears: 23 frames, `[2, 2, 2, 2, 5, 2, 3, 5, 1, 3, 3, 3, 3, 4, 2, 4, 3, 1, 4, 4, 1, 2, 3]`
- complaint letter: 18 frames, `[2, 3, 3, 2, 3, 2, 6, 8, 1, 3, 4, 2, 3, 2, 2, 3, 6, 9]`
- houseplants: 21 frames, `[1, 8, 3, 1, 2, 8, 6, 1, 1, 2, 3, 1, 5, 2, 3, 2, 1, 1, 5, 2, 6]`

At temperature 0.6 no prompt repeated its sequence, but the per-prompt means stayed apart (2.35, 2.67, 5.52, 3.69 tokens per frame).

## What this shows

1. **Root can check a guessed prompt at temperature 0.** The sequence is fixed for a prompt, and the models are open. An attacker who runs a guessed prompt on the same models and gets the same sequence has strong evidence for the guess. The 4 sequences already differ by the second frame, so the sequence identifies the prompt among these guesses. This test did not run the attacker's side on a second engine; it shows the two conditions that the attack needs.
2. **Root learns something about the text at temperature 0.6.** Formulaic text (the complaint letter) gives a much higher acceptance than descriptive text. The pattern does not repeat, so an exact guess check is harder, but the mean still separates kinds of text.
3. The network does not see the pattern (padded frames, sent after generation ends).

The claim's limit "the speculative-step pattern may carry information about the reply content" is therefore **confirmed**, and it is larger than "rough type of text": at temperature 0 it supports a guess check of the exact prompt.

## Decision

The operator's decision of 2026-10-24 stands: documented as a stated limit, not fixed. A fix must send a fixed number of tokens per frame at fixed times (for example, one frame per fixed time slot, or all frames at the end of generation); padding each frame alone hides the count per step but not the number of steps. No fix is designed or tested.

## Gap: the temperature-0 guess check (documented 2026-10-25, not fixed)

Operator decision 2026-10-25: record this as an open gap. No fix is built.

The guess check needs two conditions. If one of the two is removed, the check stops.

1. The pattern repeats: at temperature 0 the same prompt gives the same token-count sequence.
2. Root sees the pattern: the child writes one frame to the engine for each step, and `fs_usage` shows the byte count of each frame.

Facts from the code that set the fixes:

- Speculative decoding is the only decode path in Splash (Splash `README.md`: "Speculative decoding is the decode path in Splash, not an option"). The Metal graph always has one anchor row and seven proposal rows (`model/Runtime.mm:2196`).
- The child can keep fewer tokens for each step with the same graph (`laneResult.maximumRetained`, `model/Runtime.mm:2200`).
- The engine makes a new random seed for each chat (`SplashBackend.swift:74`). At temperature 0 the seed has no effect.

Possible fixes (none built or tested):

| Fix | What it stops | What stays | Cost |
|---|---|---|---|
| 1. The child sends the whole reply in one frame when generation ends | The per-step sequence | Total generation time, which shows the number of steps: one number for each reply, which repeats at temperature 0. Not measured: whether root can count GPU steps with `ktrace` or `powermetrics` | Small change in the child and the engine wire code. No speed loss. New pins |
| 2. The engine refuses temperatures below a minimum | Exact repeat of the sequence (the seed is secret) | The predictability signal measured at 0.6. A temperature near 0 is almost greedy, so the minimum needs a test | Consumers lose exact repeatable output |
| 3. The sealed child keeps one token for each step (`maximumRetained` = 1) | The sequence and the predictability signal | Reply length (a stated limit) | Decoding 2 to 5 times slower (measured means 2.35 to 5.52 tokens per step). New pins |

A setting that selects fix 3 or fast decoding is not acceptable: it gives consumers a less private mode.

Not measured: whether a second Mac or a different GPU gives the same sequence for the same prompt (the attack needs this), and whether root can rebuild text that it cannot guess from the sequence alone.
